# Roadmap part: performance and memory

Part of [`ROADMAP.md`](../ROADMAP.md). This part holds the open speed and memory work (the renderer rewrite's next steps, the Sodium audit, the memory audit) and the changelog of the ports that did it: C2ME (workers for meshing, light, I/O, populate, lazy noise), Embeddium / Sodium (arena, 16-byte vertices, occlusion culling), Radium, ModernFix, Noisiumed, FastNoise, FerriteCore, ImmediatelyFast (font atlas, sign text cache, GPU error traces), frame-cost passes, culling.

## OpenGL ES 3.2 renderer (2026-10-22)

A second, native renderer next to wgpu: `Renderer:` Auto / Vulkan / OpenGL ES in Video Settings (`renderer:` in `options.txt`, next start). Not compiled, not run (no Rust toolchain in the session); the GLSL was compiled on Mesa and a lit quad drawn through the chunk program (`tools/gles_check.py`).

- **Seam.** `gpu/gfx.rs`: `Buf` (wgpu or GL buffer) and `Gfx` (make / write a buffer) are what `ChunkManager` pages, `Lod`, `ItemMesh` and `Outline` use, so the meshes are built once for both. The draw loops became `ChunkManager::for_each_run` and `Lod::for_each_tile`; wgpu's `draw_ranges` / `draw` are wrappers over them. `WorldDraw` carries one frame's CPU result to `Backend::draw_world`; the wgpu passes moved into `backend.rs` unchanged.
- **GLES side** (`src/gles/`): `sys.rs` (EGL via `dlopen`, GL entry points through `eglGetProcAddress`; no crate, links on any host), `mod.rs` (`Gl`: ES 3.2 context, 3.0 fallback; buffers freed through a delete queue; the context moves from the init thread to the render thread), `shaders.rs` (GLSL ES 3.00 ports of every WGSL program in use: chunk x6, final, HUD, panorama, weather, sky dome / fan / stars / sun and moon), `renderer.rs` (the two passes).
- **Conventions.** GL clip depth is -1..1: every view-projection is premultiplied by `depth_fix()` (tested). The window surface is plain RGBA8 and the final shader encodes sRGB; the scene is `SRGB8_ALPHA8`. Images are sampled with the uv they were uploaded with, so nothing is flipped.
- **Vulkan optimisations carried over:** 16-byte vertex + shared quad index buffer, pages (VAO cached per page / tile), layer order and sort direction, MSAA kept in tile memory (`EXT_multisampled_render_to_texture`, else blit + `glInvalidateFramebuffer`), alpha-to-coverage only on cut-outs and only when multisampled, `Post: Fast`, MSAA / Auto by GPU (`present::resolve`), dynamic resolution (swap time = the wait), depth invalidated at the end of the pass, orphaned streaming buffers. Shared CPU side untouched.
- **Not carried over (no GL equivalent worth it):** pipeline caches, bind-group dynamic offsets (the origin is one `glUniform3f` per chunk run). Possible next: `GL_EXT_disjoint_timer_query` for real GPU time in the DRS, `glProgramBinary` shader cache, `glMultiDrawElements` where `EXT_multi_draw_arrays` exists.
- **Check first on the phone:** the log line `GLES init: ... | context 3.2, max samples N, tile-memory MSAA true/false`; if the title screen is black, `Renderer: Vulkan` brings the old path back.

## Memory and speed: what is still missing (follow-up of the FerriteCore audit, 2026-10-21)

Nothing here is written. None of it was measured: there is no phone and no Rust toolchain in the sessions that audited it, the sizes come from the code. Per loaded chunk the arrays are `blocks` 32 KB + `light` 32 KB + `data` (metadata, now lazy) 16 KB at most, and the light thread holds a second copy of `blocks` and `light`. Do 1 first; the rest in this order (smallest and safest first).

1. **Measure.** RSS at the usual render distance on the phone, split into chunk arrays, LoD tiles (`KEEP_TILES` 600) and GPU pages. Every item below is a guess until this exists.
2. **One copy of `blocks` / `light` for the render thread and the light thread** (`Entry.blocks` / `Entry.light` vs `LChunk.blocks` / `LChunk.light`, 64 KB a chunk twice over). `Arc<[u8]>` with `Arc::make_mut` on every write; the writers are `ChunkManager::set_block*`, populate (`put_region`), the light thread's `Report`. This is the upgrade the `ponytail:` note at `MeshJob` already names, and it also removes the `Snap` copy of a mesh job (5 x 80 KB, memcpy speed on the render thread).
3. **Light reports as deltas.** `Report.chunks` sends the whole 32 KB light array of every chunk touched in a 5 ms slice (`LIGHT_SLICE`); send the changed range, or the section, instead.
4. **Neighbour slabs for mesh jobs.** The mesher reads a neighbour chunk only through `rid`, `meta_at` and `lv` at `x` or `z` in `-1..=16`, which is one border plane (x = 15 or 0, z = 15 or 0). Snapshotting that plane (about 5 KB) instead of the chunk (80 KB) is ~100 KB a job instead of 400 KB. Needs a new `build_split_tinted` argument type and edits to its ~40 tests; skip it if 2 lands (the copy is gone then).
5. **Per-section storage of `blocks` and `light`** (FerriteCore's single-value `PalettedContainer`): a 16-high section that is all air, all stone or all sky light is one value. The big saving (about half of a chunk's arrays), and the invasive one: the index is `(x << 11) | (z << 7) | y` with `y` fastest, so a section is not contiguous, and every reader takes the raw slice (`mesh`, `light`, `save`, `populate`, LoD ingest). Its own milestone, with the save format converted on load and save.
6. **Section-level lazy `Nibbles`.** Metadata is lazy per chunk since 2026-10-21 (no array while all 0); per 16-high section would keep 2 KB where a chunk has only ground-level tall grass. Needs a private layout and `bytes()` building the McRegion order (used by `save` and the golden hash in `populate`).
7. **LoD memory.** `Span` is 7 bytes of which 3 are a tint that is white for everything but grass and leaves: a palette index makes it 5; `Cell` is 24 bytes (`x`, `y`, `z` as `i32`); `Tile.cov` is a `Vec<bool>` (a bitset is 8 times smaller); identical columns could be interned (the hit rate on natural terrain is probably low: measure).
8. **Cheaper hashing outside the chunk map.** `ticks.rs` (`pending`, `notes`) and `gen/overworld.rs` (`cols`) still hash with SipHash; `chunks.rs` has a `KeyHasher` for this. Speed, not memory; small.

## Renderer rewrite (lightweight frame)
- Frame = 2 render passes (was 3, 2026-10-21 (8)): scene (sky, solid, far terrain, cutout, entities, water, rain) at `RENDER_SCALE`, 4x MSAA resolved into an 8-bit sRGB target in tile memory (colour and depth `Discard`ed, 1 sample if the adapter has no 4x: `present::pick_samples`); then ONE full-screen pass at surface size: (FXAA only without MSAA) + CAS + upscale + vignette + the HUD (`render/present.rs`).
- Chunk shader (`gpu/pipeline.rs`) lights and fogs per VERTEX like b1.7.3; one atlas read per pixel; Sodium-style layers: `solid` (no `discard`, tiler HSR works), `cutout`, `lod`, `water`. `build_job` splits the triangles by tile alpha (`atlas::is_cutout`); `draw_ranges(Layer)` walks a near-to-far order cached once a frame.
- Removed: Photon (G-buffer, deferred, shadow maps, VL, GTAO, clouds, HDR post chain, pack/fog/noise) and its assets' code paths. `render/color.rs` keeps `legacy_lin`. `LEGACY` stays as a switch for the mesher and the sky.
- Not measured on a device (no phone here); verified by `cargo test` on lavapipe (`frame_renders_headless`, shader validation, `is_cutout`).

### Sodium features still to port (audit of `sodium-dev`, 2026-10-20; read from file names and the mc-rs code, not from the Java bodies)
Already in: occlusion culling (`embeddium::cull`, `vis`), render layers solid / cutout / water (`TerrainRenderPass`), the buffer arena (chunk pages, see the 2026-10-20 changelog entry; not compiled yet). Measure on the phone first (step 1 above): if the frame is not CPU-bound, none of this pays.

Cheap, in this order:
1. **Shared quad index buffer** (`SharedQuadIndexBuffer`) - WRITTEN 2026-10-20 (not compiled, not run; see the changelog): one buffer of `0,1,2,0,2,3 + 4n` for every mesh instead of an index run per chunk; index memory down by about a third and no index upload. The mesher must emit quads sorted by section, not indices (`by_section` today sorts triangles). Needs `base_vertex` or one shared buffer per page sized to the page's vertex count; the pages already write shifted indices, so this replaces that.
2. **16-byte vertex** (`embeddium/src/vertex.rs`) - WRITTEN 2026-10-20 (not compiled, not run; same as step 3 above): chunk-local u16 position + per-draw origin, u16 uv, packed light/tint. Touches `Vertex::layout`, `vs_main`, `vs_water`, `build_job` and `Pages::put` (`VERT_BYTES`).
3. **Upload budget by size** (`UploadResourceBudget`, `UploadDurationEstimator`) - WRITTEN 2026-10-21 (4) (not compiled, not run; see the changelog): a byte + time budget per frame, fed by the measured cost of `Pages::put`, replaces the fixed count and time (`CHUNK_WORK_BUDGET` is gone, `MESH_PER_FRAME` is a guard). `MeshTaskSizeEstimator` is not ported: the size is exact when the mesh is uploaded.

Heavier:
4. **Async occlusion walk** (`CullTask`, `AsyncCameraTimingControl`, `CullType.WIDE`) - WRITTEN 2026-10-23 (not compiled, not run; see the changelog): `update_visible` walked the occlusion graph on the render thread every frame (at 16 chunks the biggest CPU cost of the frame). Now the walk ignores the frustum and the eye's place in its section, is redone on a worker only when the eye changes section or a chunk's `vis` changes, and a frame only tests it against the frustum.
5. **Per-quad water sorting** (`ChunkBuilderSortingTask`): water is sorted per chunk only (step 6 above). Sorting quads fixes blend artefacts but means re-uploading the water indices when the eye moves (they are a separate run of the page, so only that run is rewritten).
6. **Light data cache + smooth lighting** (`ArrayLightDataCache`, `SmoothLightPipeline`, `AoFaceData`): only if the mesher gets per-vertex ambient occlusion; the b1.7.3 look (light per vertex from the cell) does not need it.

Not applicable, left out on purpose: multi-draw and persistent mapping (not in wgpu's downlevel set, none on a GLES fallback), mixins and the Forge / Fabric glue, the options screen, `ColorProviderRegistry` (biome tints are `biome_tints` already).
