# Roadmap: Minecraft b1.7.3 -> Android in Rust

Fresh start. One milestone per session. Vanilla names. Vulkan, with OpenGL ES (wgpu's second backend) as the automatic fallback.
Own simple save format (M7 dropped McRegion). Client-only, single player.

## Scope

Out of scope on purpose (not planned, not tracked): **M9 audio**, **M10 multiplayer** (`Packet*`, `NetClientHandler`),
**M13 further optimization** (frustum culling is in; greedy meshing, profiler and the rest are dropped), McRegion saves.
Everything below is gameplay or content that exists in the b1.7.3 sources and is missing or wrong in mc-rs.
The list comes from an audit of `Block.java`, `Item.java`, `EntityList`, `TileEntity`, `CraftingManager` and every `Block*`
class with an interaction hook, checked against the Rust code (read, not run: no Rust toolchain in that session).

## Build
- Workspace at `mc-rs/`
- `cargo test -p tectonic` runs the Tectonic crate's tests on a plain host (no Android bits); `tools/tectonic.py golden` prints the numbers they compare against.
- `cargo test --lib` runs the unit tests (Android host such as Termux; see README). Several newer tests are compiled and ran, not yet to be tested: run them first.
- `cargo run` boots a desktop window (Metal / Vulkan / GL depending on host).
- APK via GitHub Actions `cargo apk build --release` -> `MinecraftB173Rust.apk`.
- A long-lived debug keystore at `keystore/debug.keystore` signs the release
  APK in CI. The same keystore is what `cargo apk build --release` expects at
  `~/.android/debug.keystore` with password `android` if you build locally.

## Source-of-truth rule

Anything that cannot be diffed against the b1.7.3 Java sources or the
decompiled `minecraft/` tree is marked `// UNVERIFIED:` in the code. PRs
that fix UNVERIFIED items should drop the marker and link the source line
they matched.

## Working rule (AGENTS.md)

Lazy senior dev: read the Java, trace the flow, reuse what exists (the arrow path, `Explosion`, `shaped(..)`, the tick
table), one runnable check per non-trivial piece, `ponytail:` comment on every deliberate shortcut. Fewest files possible.
Order of work: always the easiest item first.

## Renderer rewrite (lightweight frame)
- Frame = 3 render passes: scene (sky, solid, far terrain, cutout, entities, water, rain) into an 8-bit sRGB target at `RENDER_SCALE`; pass A FXAA + CAS at scene size; pass B upscale + vignette + HUD (`render/present.rs`). Depth is `Discard`ed.
- Chunk shader (`gpu/pipeline.rs`) lights and fogs per VERTEX like b1.7.3; one atlas read per pixel; Sodium-style layers: `solid` (no `discard`, tiler HSR works), `cutout`, `lod`, `water`. `build_job` splits the triangles by tile alpha (`atlas::is_cutout`); `draw_ranges(Layer)` walks a near-to-far order cached once a frame.
- Removed: Photon (G-buffer, deferred, shadow maps, VL, GTAO, clouds, HDR post chain, pack/fog/noise) and its assets' code paths. `render/color.rs` keeps `legacy_lin`. `LEGACY` stays as a switch for the mesher and the sky.
- Not measured on a device (no phone here); verified by `cargo test` on lavapipe (`frame_renders_headless`, shader validation, `is_cutout`).

2. **16-byte vertex** (`embeddium/src/vertex.rs`) - WRITTEN 2026-10-20 (not compiled, not run; same as step 3 above): chunk-local u16 position + per-draw origin, u16 uv, packed light/tint. Touches `Vertex::layout`, `vs_main`, `vs_water`, `build_job` and `Pages::put` (`VERT_BYTES`).
3. **Upload budget by size** (`UploadResourceBudget`, `MeshTaskSizeEstimator`, `UploadDurationEstimator`): `MESH_PER_FRAME` and `CHUNK_WORK_BUDGET` are fixed counts and times today; a byte budget per frame, fed by the measured cost of `write_buffer`, smooths the frames where many chunks finish at once.

Heavier:
4. **Async occlusion walk** (`CullTask`, `AsyncCameraTimingControl`): `update_visible` runs on the render thread every frame. Only worth it with a render distance well past 4 chunks.
5. **Per-quad water sorting** (`ChunkBuilderSortingTask`): water is sorted per chunk only (step 6 above). Sorting quads fixes blend artefacts but means re-uploading the water indices when the eye moves (they are a separate run of the page, so only that run is rewritten).
6. **Light data cache + smooth lighting** (`ArrayLightDataCache`, `SmoothLightPipeline`, `AoFaceData`): only if the mesher gets per-vertex ambient occlusion; the b1.7.3 look (light per vertex from the cell) does not need it.

Not applicable, left out on purpose: multi-draw and persistent mapping (not in wgpu's downlevel set, none on a GLES fallback), mixins and the Forge / Fabric glue, the options screen, `ColorProviderRegistry` (biome tints are `biome_tints` already).
